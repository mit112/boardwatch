## Where this spec was WRONG against the code

1. **T31: seeding the template silently disarms the test-user fixture.**
   `tests/conftest.py:write_test_resume_template` wrote its edited template only `if not
   target.is_file()` — its docstring reasoning that this "composes with a caller that may have
   written its own template earlier". Once `init` writes one, that guard fires on the **bundled
   placeholder**, so every fixture building a properly configured user (`init` + `tailor init` +
   this) was left holding unedited placeholder identity, which `_validate_template` then refused
   exactly as it would for a real user. **86 pipeline tests failed on the first gate, all one
   cause.** The handoff's acceptance list ("the refusal test from T2 unchanged") did not
   anticipate it. Fixed in the same commit: the helper still yields to a caller's own template
   and now overwrites the placeholder seed.

2. **T36: `board_scans` cannot support the model the handoff points at** ("model it from the
   tick's own per-board timings the way the 2026-08-28 comment did"). Run 2's 288 `board` rows
   sum to **127 s** against a 10,716 s scan stage — they time the listing enumeration only. A
   model built on posting counts instead is also wrong and **its own null control says so**: run
   2's 17,962 Greenhouse postings would be a 17,962 s critical path at 1.0 s/host pacing, longer
   than the entire measured scan — Greenhouse returns bodies inline (87 boards, 118.8 s). The
   only usable instrumentation is `funnel-<id>.json` → `scan.fetch_cost`.

3. **`config.toml`'s `scan_workers` comment is factually stale.** It says "8 is the schema's
   ceiling (`scan_workers` is `le=8`)". `core/settings.py:114` reads
   `Field(default=4, ge=1, le=32)` since SP1. Any T36 edit must correct the comment.

4. **`projection/shell.py`'s module docstring was the DESIGNATED record of the gap T32 closes,
   and three exit-0 gates walked past it.** It still read "**But `shell_source`'s CONTENT is not
   covered by any digest in v1** … no digest moving and no re-approval required" — which T32
   makes false, and which D-167 explicitly delegated *there*. Anyone grepping `shell_source`
   would have concluded T32 was unshipped. Found by an independent read-only review of the diff,
   not by the gate — the same lesson as D-469.

5. **`docs/projection-rendering.md` misdescribed the approval gate, and pre-dates T32.** It said
   the approval binds "to the bundle digest it was made against". D-167 replaced that with the
   CONTENT digest precisely so an unrelated revision promotion does *not* stale an approval.
   Corrected — but **only the shell clause is T32's; the bundle-digest error was already shipped.**
