### T15 — board-level shrink guard (design ruled)

**Files:** `scan/apply.py:62-107` (`apply_board`), `_process_missing` at 465.
**Ruling:** the guard fires on **zero only, not a ratio**: a `complete` snapshot listing 0 postings
for a board that currently holds ≥1 open posting is treated as **unchanged** — no miss counted, no
validators persisted, counted on the scan summary as `empty_complete_guarded` and printed by board.

guard has one: the moment the board lists ≥1 posting again, normal miss counting resumes.

postings in the store; the liveness probe withholds them at delivery, so the cost is store hygiene,
not a delivered dead lead. The fleet-level guard in the runner took the same trade.
