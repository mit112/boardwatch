### T33 — a chrome detector that detects chrome: board-scoped boilerplate (M, measure first)
**Premise:** site furniture is the text that is IDENTICAL across many postings of the same board;
a JD is the text that is not. This is language- and heading-independent, which is exactly what
`count_section_markers` was not.
**Measurement, read-only, over the live store's open bodies:** for each board with ≥ 10 open
postings, split each body into lines (strip, drop empties), count in how many of the board's
bodies each line occurs, and call a line *chrome* when it occurs in ≥ 80% of them. For each body
compute `residual_chars` = characters in non-chrome lines. The candidate class is
`residual_chars < MIN_BODY_CHARS` (reuse the existing constant). Report: held count and rate
corpus-wide, by provider, and **twenty held bodies chosen at random, printed in full**, so the
class is inspected rather than trusted. `MIN_BODY_CHARS` and the T26 structural class both live
in `lanes/quality.py`; the new class goes beside `_is_machine_shaped`. **Null controls:** (a) a synthetic board of 10 bodies
sharing a 200-char header must produce exactly that header as chrome and nothing else; (b) run
the same measurement with the threshold at 95% and at 50% and report all three — a class that
swings by an order of magnitude across thresholds is not a class.
**Stop condition:** > 1% held, or held bodies that read as JDs on inspection ⇒ report and stop,
no code. **Ship condition:** ≤ 1% and the printed sample is chrome. Then add it as a STRUCTURAL
class in the same catalog T26 used (machine-shaped), with the same drain, and the measurement
script committed under `tools/` so the number is re-derivable. The threshold is a constant with
the measured corpus figure in its docstring.
**Boards with < 10 open postings are out of scope by construction** — say so in the docstring.
