## 2. Where the spec was wrong against the code

1. **"Landing T47 re-keys NOBODY" is true of `rules_hash` ONLY.** `digested_modules()` is
   `(catalog.py, detect.py, resolve.py, engine.py)` and T47 edits **two** of them, so
   `engine_version` moved at MERGE (`1+d89b423701e5` → `1+8c8694b96ca8`), and
   `preflight._pending` filters on `engine_version` as well as the two hashes. Every open posting
   was therefore pending from the merge, not from the value being set. Harmless in this sequence
   (merge → set → one run, so they are evaluated exactly once); it would have cost a full extra
   re-evaluation had any run fired in the gap.
2. **`GateTier` has FIVE fields, not four**: `enabled`, `claude_config_dir`, `model`,
   `batch_size` (13), `call_timeout_s` (300). T49's scope is five keys.
3. **`config.toml` already existed with six live settings and no `[gate]` table.** The block had
   to be APPENDED; a write would have silently dropped `scan_workers`, the lane budgets and the
   location filter mode. Backup kept beside it.
4. **`set_policy` rebuilt `Policy(families=...)` from scratch**, discarding every other field.
   Inert while `families` was the only field; it would have wiped the ceiling the first time
   `policy set` ran after T47. Fixed in the same change (an orphan the change itself created) and
   pinned in both orders.
5. **The plist's PATH could not reach `claude`.** `gate_judge` invokes it as a bare `argv[0]`
   resolved against the passed env's PATH; launchd inherits no shell environment, and the plist
   carried `/opt/homebrew/bin:/usr/bin:/bin:/usr/sbin:/sbin` while `claude` lives in
   `<home>/.local/bin`. **Every unattended judge batch would have raised `FileNotFoundError` and
   failed open.** The interactive shell has that directory, so a manual run would never have shown
   it — only the tick would break. Fixed textually (comments survive, `plutil -lint` OK, backup
   beside it). Every other run dependency was already reachable, which is why runs 1–3 were clean.
6. **The tick fires 04:00, not the 06:00 the handoff states.** `StartCalendarInterval` is Hour 4.
7. **`experience_unconfirmed` is not recoverable from any persisted artifact.** The queue's
   `details.json` carries `verdict` and `target_flag` only; the review reason is computed in
   `review_gate.classify` and surfaced through the web API, never written to disk. The handoff's
   "39 of 80 before" cannot be reproduced from run 4's output. Recorded as an instrumentation gap,
   not a number.
